### 🎙️ 오늘의 팟캐스트
Jekyll로 한 페이지에서 여러 형식 파일 생성하기

&nbsp;

### 📌 에피소드 주요 내용
- Jekyll은 기본적으로 하나의 마크다운 파일에서 하나의 형식(HTML)만 생성하는 제약이 있음
- 플러그인, 다중 출력 폴더, 후처리 스크립트 조합 등 세 가지 해결책 존재
- GitHub Actions와 Node.js를 활용한 자동화 방식이 실무에서 가장 효율적이고 유지보수 용이함

### 🎧 전체 대본
**지혜:** 안녕하세요, 팟캐스트 '코딩과 인생' 진행자 지혜입니다. 오늘은 특별한 손님을 모셨는데요, 정보시스템학을 오랫동안 가르치셨던 노교수님입니다. 안녕하세요, 교수님!

**박교수:** 안녕하세요. 반갑습니다. 은퇴 후 학생들을 위해 온라인 강좌 자료를 정리하다가 흥미로운 문제에 마주쳤는데, 그것이 오늘 이야기할 주제입니다.

**지혜:** 오! 은퇴하신 후에도 학생들을 위해 노력하시다니 정말 멋있으세요. 그러면 어떤 문제를 만나셨어요?

**박교수:** GitHub Pages와 Jekyll을 사용해 강의 자료를 관리하고 있었습니다. 그런데 강의 일정을 한 번 올릴 때, 학생들은 웹 페이지에서도 보고 싶어 하고, 동시에 자신의 Google Calendar나 Outlook 같은 캘린더 앱에 자동으로 추가되는 iCal 형식도 원했던 것이지요. 문제는 같은 내용을 두 번 관리해야 한다는 것이었습니다.

**지혜:** 아, 그러니까 하나의 정보를 여러 형식으로 동시에 만들고 싶은 거군요. Jekyll은 원래 그게 안 되나요?

**박교수:** 정확한 지적입니다. Jekyll은 기본적으로 마크다운 파일 하나당 하나의 HTML 파일만 생성합니다. 현실의 콘텐츠는 훨씬 복잡하지만 말이에요. 학술 자료는 웹 버전, PDF, 인쇄 버전이 필요하고, 이벤트는 HTML과 iCal이 동시에 필요합니다. 저는 Jekyll 공식 이슈 게시판에서 이에 대한 논의를 발견했습니다.

**지혜:** 와, 그래서 해결책을 찾으셨나요?

**박교수:** 네, 세 가지 방법이 있습니다. 첫째는 Jekyll 플러그인을 만드는 것이고, 둘째는 출력 폴더를 여러 개로 나누는 것입니다. 하지만 저는 세 번째 방법을 선택했어요. Jekyll 빌드 후에 Node.js 스크립트로 후처리 단계를 추가하는 것이지요. GitHub Actions 워크플로우에 이를 포함시켜서, 마크다운 파일 하나를 수정하면 자동으로 모든 형식이 업데이트되도록 했습니다.

**지혜:** 오, 자동화까지! 그러면 유지보수가 훨씬 쉽겠네요.

**박교수:** 그렇습니다. 대학원 때는 이론적으로 완벽한 솔루션을 추구했지만, 실무에서는 작동하는 솔루션이 중요합니다. Jekyll의 제약을 원망하기보다는 그 위에 얹어서 필요한 기능을 만드는 것이 더 효율적이더군요. 더 자세한 내용과 실제 구현 코드는 블로그 원문에서 확인하실 수 있어요. 혹시 비슷한 문제를 겪고 계신 분들께 도움이 되기를 바랍니다!

**지혜:** 정말 실용적이고 좋은 경험담이었습니다. 노교수님, 오늘 시간 내주셔서 감사합니다!
