### 🎧 전체 대본
**지혜:** 안녕하세요, 지혜입니다. 오늘은 노교수님과 함께 Jekyll 블로그를 운영할 때 겪는 흔한 문제에 대해 얘기해보겠습니다. 교수님, 안녕하세요!

**박교수:** 안녕하세요. 이렇게 팟캐스트에 초대해주셔서 감사합니다. 제가 GitHub Pages에 Jekyll 블로그를 구축한 지 얼마 안 되었는데, 어느 날 갑자기 빌드 프로세스가 멈춰버렸거든요. 정말 답답했던 경험입니다.

**지혜:** 와, 그런 일이 있으셨군요. 어떤 증상이었어요?

**박교수:** 빌드가 자꾸 시간 초과되고, 로그에는 '이미지 변환 작업'이라는 메시지만 반복되었습니다. 원인을 찾기 위해 대여섯 시간을 투자했을 정도니까요. 알고 보니 이미지 처리 과정에서의 병목 현상이었습니다. 특히 Chirpy 테마를 사용하면 자동으로 여러 해상도의 썸네일을 생성하려고 시도하는데, 손상된 이미지 파일이 섞여있으면 무한 루프에 빠지게 되는 것이죠.

**지혜:** 손상된 이미지라니요? 어떻게 그런 일이?

**박교수:** 제 경우엔 대학 시절 자료를 스캔한 PDF를 JPEG으로 변환해서 업로드했는데, 변환 과정이 완전하지 않아 헤더가 손상된 파일들이 있었습니다. 실제로 로컬에서 빌드를 시도했을 때 20분 이상 같은 파일을 반복 처리하는 것을 봤어요. 그제야 문제를 깨달았죠.

**지혜:** 그렇다면 이런 문제를 어떻게 해결하셨어요?

**박교수:** 세 가지 방법이 있습니다. 첫째는 이미지를 미리 최적화하는 것입니다. 모든 이미지를 웹 표준인 72 DPI로 통일하고, 해상도는 1200에서 2000픽셀 사이로 유지하세요. 저는 JPEG을 85% 품질로 압축했더니 빌드 시간이 절반으로 줄었습니다. 둘째는 의심 파일을 찾아서 제거한 후 재업로드하는 방법입니다. 로그에서 반복되는 파일을 삭제하고 빌드하면 원인을 파악할 수 있죠. 셋째는 설정 파일에서 자동 이미지 최적화 기능을 일시적으로 비활성화하는 것입니다.

**지혜:** 정말 실용적인 조언들이네요. 로그를 읽는 팁도 있으신가요?

**박교수:** 물론이죠. GitHub Actions의 'Show all' 버튼으로 전체 로그를 펼쳐야 합니다. 이미지 문제일 때는 특정 단계에서 진행 표시기가 움직이지 않고, 로그 끝이 GraphicsMagick 관련 메시지로 끝나는 특징이 있어요. 타임아웃 오류가 나타나면 그것이 명백한 신호입니다.

**지혜:** 사실 이런 문제들이 데이터 검증의 기본 원칙과도 연결되는군요?

**박교수:** 정확한 지적입니다. 투입하는 자료의 품질을 먼저 보장해야 시스템이 안정적으로 작동한다는 겁니다. 제 연구 경험에서 배운 가르침이 이곳에서도 적용되더라고요.

**지혜:** 정말 좋은 말씀입니다. 더 자세한 내용은 원문 블로그에서 확인하실 수 있으니, 꼭 읽어보세요!
