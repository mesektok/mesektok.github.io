## 은퇴 후 블로그를 시작하며 겪은 예상 밖의 문제

작년 봄, 서울대학교에서 30년간 경제학을 가르친 후 은퇴한 저는 Jekyll 블로그로 강의 노트와 경제 칼럼을 정리하기 시작했습니다. 처음에는 HTML 페이지만으로 충분하다고 생각했는데, 문제가 생겼습니다. 학생들이 강의 일정을 달력에 넣고 싶다고 했고, 일부 독자들은 PDF로 다운로드할 수 있기를 원했습니다.

한 포스트마다 세 가지 파일을 수동으로 만들어야 했습니다. HTML은 블로그에, iCal은 따로, PDF는 또 따로. 더 큰 문제는 강의 일정이 변경될 때였습니다. 세 개의 파일을 모두 수정해야 했고, 자주 일관성이 맞지 않았습니다. 이때 Jekyll의 한계를 느꼈습니다.

## Jekyll의 기본 한계와 해결책의 필요성

Jekyll의 기본 구조는 하나의 마크다운 파일이 하나의 출력 파일을 생성하도록 설계되어 있습니다. `_layouts` 폴더의 레이아웃을 설정하고 `output` 형식을 지정하면 되는데, 동시에 여러 형식을 출력할 수는 없었습니다.

GitHub의 공식 이슈 #3041에서 이 문제가 제기되었습니다. 개발자들도 같은 콘텐츠로부터 HTML뿐만 아니라 iCal, JSON, RSS 등 다양한 형식을 자동으로 생성하고 싶었던 것입니다.

저는 여러 가지 해결책을 시도했습니다. 첫 번째는 Jekyll의 플러그인 시스템을 활용하는 것이었습니다. `_plugins` 폴더에 루비 스크립트를 작성하여 포스트를 처리한 후 여러 형식으로 변환하는 방식입니다. 처음에는 복잡해 보였지만, 결과는 놀라웠습니다.

## 실제 구현 방법: 플러그인으로 다중 포맷 자동 생성

저는 `multi_format_generator.rb`라는 커스텀 플러그인을 만들었습니다. 이 플러그인은 포스트의 프론트매터에 `formats: [html, ical, json]`이라고 지정하면 자동으로 세 가지 파일을 생성합니다.

구체적인 방법은 다음과 같습니다. 먼저 포스트의 프론트매터에 원하는 출력 형식을 명시합니다. 그 다음 `_layouts` 폴더에 각 형식별 레이아웃 파일을 준비합니다. 예를 들어 강의 공지사항이라면 `post.html`, `post.ical`, `post.json` 세 가지 레이아웃을 만드는 것입니다.

루비 플러그인에서는 Jekyll의 Post 객체를 순회하며 각 포스트마다 지정된 형식의 수만큼 출력 페이지를 생성합니다. 이때 파일 확장자도 자동으로 결정됩니다. `post.md`는 `post/title/index.html`, `post/title/index.ical`, `post/title/index.json`으로 변환됩니다.

제 경우, 강의 공지에는 iCal 형식을 추가했습니다. 레이아웃 파일에서 Liquid 템플릿을 사용해 포스트의 제목, 날짜, 설명을 iCal 형식으로 변환했습니다. 이제 학생들은 포스트 페이지의 버튼을 클릭하면 바로 자신의 캘린더에 일정을 추가할 수 있습니다.

## 더 나은 방법: 네이티브 지원을 위한 대안

물론 이 방법도 완벽하지는 않습니다. 플러그인을 사용하면 GitHub Pages에서 직접 배포할 수 없고, 로컬에서 빌드한 후 업로드해야 합니다. GitHub Pages를 사용하려면 Actions 워크플로우를 설정해야 합니다.

더 간단한 대안도 있습니다. 하나의 포스트마다 여러 개의 마크다운 파일을 만드는 방법입니다. 같은 콘텐츠를 `post.md`, `post.ical.md`, `post.json.md`로 나누어 저장하는 것입니다. 유지보수가 어렵지만 복잡한 플러그인이 필요 없습니다.

현재는 Jekyll 커뮤니티에서 더 나은 해결책들이 논의되고 있습니다. 일부 테마와 플러그인들이 이미 다중 형식 출력을 지원하기 시작했습니다. Chirpy 테마도 최근 버전에서 기능이 확장되었으니, 공식 문서를 확인해보시기 바랍니다.

은퇴 후 블로그 운영이 이렇게 복잡할 줄은 몰랐지만, 이 과정에서 기술에 대한 이해도 깊어졌습니다. 혹시 당신도 같은 문제로 고민하고 계신다면, 당신의 상황에 맞는 방법을 선택하여 시도해보시기를 권장합니다.
