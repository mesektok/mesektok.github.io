## 은퇴 후 블로그를 시작했던 나의 경험

저는 30년간 대학에서 물리학을 가르치다가 지난해 은퇴했습니다. 그 이후 그동안 해오던 연구와 강의 자료를 정리하여 블로그에 올리기로 결심했죠. Jekyll을 선택한 이유는 간단했습니다. 깃허브에서 무료로 호스팅해주고, 마크다운으로 편하게 글을 쓸 수 있다는 점 때문이었습니다.

그런데 얼마 지나지 않아 문제가 생겼습니다. 제가 올린 강의 노트와 세미나 정보를 학생들과 동료 교수들이 다양한 형식으로 필요로 했던 것입니다. 어떤 이는 HTML 버전을 원했고, 어떤 이는 PDF로 다운로드하길 원했고, 또 어떤 이는 자신의 캘린더 앱에 동기화할 수 있는 iCal 형식을 요청했습니다. 처음에는 각각의 형식을 따로 관리했지만, 이는 매우 번거로웠고 오류가 발생하기 쉬웠습니다.

## Jekyll의 원래 한계와 왜 이것이 문제인가

Jekyll의 기본 구조를 이해하려면 먼저 그 작동 원리를 알아야 합니다. Jekyll은 마크다운 파일을 입력받아 정해진 레이아웃에 따라 한 가지 형식의 출력물을 생성합니다. 기본값은 HTML이죠. 한 개의 포스트 파일에서 하나의 HTML 페이지만 생성된다는 뜻입니다.

이것이 많은 사용자들에게 불편함을 초래했습니다. 특히 블로그를 단순한 웹사이트로만 사용하지 않는 경우 말입니다. 예를 들어 행사 일정을 공지할 때, 방문자들이 HTML 버전을 볼 수도 있고 자신의 구글 캘린더나 아웃룩에 바로 추가할 수 있는 iCal 파일도 원합니다. 학술 자료를 배포할 때는 온라인 읽기용 HTML과 오프라인 읽기용 PDF가 모두 필요합니다.

2015년 이 문제를 제기한 개발자도 같은 고민을 했습니다. 그는 각 포스트마다 HTML 버전과 iCal 버전을 동시에 생성하고 싶었던 것입니다. 현재 Jekyll의 구조로는 이것이 불가능했습니다.

## 실제 해결책: 커스텀 플러그인과 레이아웃 활용법

다행히 Jekyll의 강점은 확장성입니다. 이 문제를 해결하기 위해 여러 방법이 개발되었습니다. 저도 시행착오를 거쳐 결국 실용적인 솔루션을 찾았습니다.

**첫 번째 방법은 커스텀 Generator 플러그인을 작성하는 것입니다.** Jekyll의 플러그인 시스템을 활용하면 빌드 과정에서 추가 파일을 생성할 수 있습니다. 저는 루비로 간단한 플러그인을 작성했습니다. 각 포스트를 읽은 후, YAML 프론트매터에 정의된 `formats` 항목을 확인하고, 지정된 모든 형식으로 파일을 생성하도록 했죠.

예를 들어 포스트 파일의 프론트매터에 다음과 같이 작성합니다:

```yaml
---
title: "2026년 가을학기 물리학 세미나"
formats:
  - html
  - ical
  - json
---
```

그러면 플러그인이 자동으로 같은 콘텐츠로 .html, .ics, .json 파일을 생성합니다.

**두 번째 방법은 다중 레이아웃 시스템입니다.** 각 형식별로 별도의 레이아웃 파일을 만들어두고, 포스트에서 어떤 레이아웃을 사용할지 지정하는 방식입니다. 이 방법은 플러그인이 필요 없어 GitHub Pages에서도 바로 사용할 수 있다는 장점이 있습니다.

**세 번째 방법은 Jekyll의 컬렉션 기능을 활용하는 것입니다.** 같은 콘텐츠에 대해 여러 개의 컬렉션을 설정하고, 각 컬렉션마다 다른 레이아웃을 적용합니다. 파일 구조는 중복되지만, 관리가 직관적이고 안정적입니다.

## 실무에서 배운 베스트 프랙티스

3년간 이 시스템을 운영하면서 배운 점들이 있습니다. 첫째, 여러 형식을 동시에 생성할 때는 마스터 파일과 형식별 변환 로직을 명확히 분리해야 한다는 것입니다. 콘텐츠는 한 곳에만 유지하고, 출력 형식만 다양화하는 방식이 가장 효율적입니다.

둘째, YAML 프론트매터를 활용한 메타데이터 관리가 중요합니다. 어떤 파일이 어떤 형식으로 생성되어야 하는지, 각 형식별로 필요한 특수 필드가 무엇인지 명확히 정의해야 유지보수가 쉬워집니다.

셋째, 형식별로 필요한 필터와 변환 함수를 미리 준비해야 합니다. HTML 출력에는 필요 없지만 iCal에는 필수인 날짜 형식, PDF에는 필요하지만 JSON에는 불필요한 스타일 정보 등이 있기 때문입니다.

제 경우, 학생들을 위한 강의 일정은 HTML 웹페이지, 자신의 캘린더에 추가 가능한 iCal 파일, 그리고 모바일 앱 연동용 JSON을 동시에 생성하도록 설정했습니다. 이제 새로운 강의 정보를 마크다운 파일 하나만 작성하면, 모든 형식이 자동으로 생성됩니다. 수정도 마찬가지입니다. 원본 파일 하나만 수정하면 모든 형식이 즉시 업데이트됩니다.

혹시 여러분도 Jekyll로 운영하는 블로그에서 다양한 형식의 콘텐츠가 필요하신가요? 댓글로 어떤 형식이 필요하신지, 그리고 구현 과정에서 어려운 점이 있으신지 공유해주세요.
