지난봄, 제 동료 교수 김 박사가 개인 블로그에서 학생들을 위한 강의록을 배포하고 있었습니다. HTML 버전도 필요하고, 프린트용 PDF도 필요했죠. 처음엔 매번 두 개의 파일을 따로 만들고 관리했는데, 수정할 때마다 둘 다 고쳐야 하니 정말 번거로웠습니다. "이게 자동으로 안 될까?"라는 그의 한숨이 바로 이 문제였습니다.

## 시니어 개발자가 자주 마주치는 문제

Jekyll을 사용하는 많은 분들이 저와 같은 고민을 합니다. 특히 학술자료, 행사 초대장, 뉴스레터 같은 콘텐츠를 관리할 때 말입니다. 한 번의 작성으로 여러 형식이 필요한 경우가 실무에선 흔하거든요.

예를 들어, 학술 세미나를 홍보한다면 웹페이지(HTML)뿐 아니라 iCal 형식의 일정 파일도 필요합니다. 방문객들이 자신의 캘린더에 바로 추가할 수 있도록 말이죠. 기업 소식을 배포한다면 웹용 HTML과 이메일 뉴스레터용 텍스트 파일이 동시에 필요할 수 있습니다. 지금까지 Jekyll은 이를 우아하게 처리하지 못했습니다.

공식 GitHub 이슈 #3041에서 제기된 바로 이 문제입니다. 한 페이지에서 여러 출력 형식을 지원하자는 제안이었는데, 당시엔 구현되지 않았습니다.

## 현재 Jekyll의 한계와 우회책

Jekyll의 기본 구조는 하나의 포스트에서 하나의 형식(주로 HTML)을 생성합니다. 레이아웃과 Liquid 템플릿 엔진이 이를 처리하죠. 하지만 같은 콘텐츠로 여러 형식을 만들려면, 우회 방법들을 사용해야 합니다.

가장 간단한 방법은 **별도의 컬렉션(Collection)을 만드는 것**입니다. `_ical` 폴더를 만들어서 iCal 형식의 파일들을 관리하고, `_posts` 폴더의 파일과 동일한 이름으로 유지하면 됩니다. 빌드 후 같은 ID를 가진 게시물끼리 링크되도록 처리하는 방식입니다.

또 다른 방법은 **플러그인을 활용**하는 것입니다. `jekyll-feed` 플러그인처럼, 특정 형식의 파일을 자동 생성하는 커스텀 플러그인을 만들 수 있습니다. Ruby로 Jekyll 플러그인을 작성하면, Post 객체를 읽어 원하는 형식으로 변환할 수 있죠.

## 실전 예시: iCal 캘린더 파일 자동 생성

제 경험상 가장 효과적인 방법을 소개하겠습니다. 강의 일정을 HTML과 iCal 형식으로 동시에 배포하는 경우입니다.

먼저 `_plugins` 폴더에 `ical_generator.rb` 파일을 만듭니다. 이 플러그인은 특정 카테고리의 모든 포스트를 읽어, 표준 iCal 형식의 파일로 변환합니다. YAML 프론트매터에 `event_date`와 `location` 같은 필드를 추가해두면, 플러그인이 이를 파싱해서 알맞은 형식으로 만들어주는 식입니다.

구체적으로는, 포스트의 Front Matter에 다음과 같이 작성합니다:

```
---
title: "2026년 여름 특강"
event_date: 2026-08-15
location: "강의실 301"
---
```

그러면 플러그인은 자동으로 `2026-08-15-summer-lecture.ics` 파일을 생성합니다. 방문자는 HTML 페이지에서 "캘린더에 추가" 버튼을 클릭하면 이 파일을 다운받아 자신의 캘린더에 임포트할 수 있게 되는 거죠.

이 방식의 장점은 포스트를 한 번만 수정하면 HTML과 iCal이 모두 자동 업데이트된다는 점입니다. 더 이상 두 파일을 따로 관리할 필요가 없습니다.

## 미래의 Jekyll은 어떨까

최근 Jekyll 커뮤니티에서는 이 문제를 더 근본적으로 해결하려는 논의가 계속되고 있습니다. 다중 출력 형식을 공식 기능으로 지원하자는 제안 말입니다. 이것이 구현되면, 복잡한 플러그인 없이도 간단한 설정만으로 여러 형식을 생성할 수 있을 것입니다.

지금 당장은 플러그인과 창의적인 폴더 구조로 이 문제를 해결해야 하지만, 그 과정에서 Ruby와 Jekyll의 내부 동작을 훨씬 깊이 있게 이해하게 됩니다. 시니어 개발자로서, 저는 이런 제약이 오히려 자신의 기술을 한 단계 업그레이드하는 기회가 된다고 봅니다.

혹시 당신도 비슷한 문제로 고민 중이라면, 지금 바로 자신의 블로그에 적용해보시기를 권합니다. GitHub 이슈를 읽고 실제 플러그인을 만들어보는 경험은 정말 값진 학습이 될 것입니다.
