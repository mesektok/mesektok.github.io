## 은퇴 후 발견한 예상치 못한 문제

지난겨울, 서울에서 은퇴한 물리학 교수인 나는 평생 모은 강의노트와 세미나 자료를 디지털화하기로 결심했다. GitHub Pages에 Jekyll 블로그를 만들어 학생들과 후학들이 자유롭게 접근할 수 있도록 하고 싶었기 때문이다. 그런데 며칠 후 예상치 못한 난제에 부딪혔다.

강의 일정과 학술회의 정보를 포스트로 올릴 때, HTML 페이지로도 보고 싶고, 동시에 학생들이 자신의 캘린더 앱(Google Calendar, Outlook 등)에 바로 import할 수 있는 iCal 형식(.ics)도 필요했던 것이다. 그런데 Jekyll은 기본적으로 하나의 마크다운 파일에서 하나의 형식만 생성한다. 

이 문제가 얼마나 많은 사용자를 괴롭히고 있는지 확인하려고 GitHub의 Jekyll 공식 저장소를 뒤져봤다. 그리고 2014년부터 제기되어온 이슈를 발견했다: "한 페이지에서 여러 형식으로 출력할 수 있을까?"

## 문제의 본질 이해하기

Jekyll의 설계 철학은 단순하다. 마크다운 파일 하나 → 선택된 레이아웃 하나 → 최종 출력 파일 하나. 이 흐름이 대부분의 블로그에는 완벽하게 작동한다. 하지만 현대의 웹 생태계는 더 복잡해졌다.

예를 들어 교육 기관의 웹사이트를 운영한다면, 학사일정 포스트 하나로부터:
- **HTML**: 웹사이트 방문자가 읽을 수 있는 형식
- **iCal**: 캘린더 애플리케이션에 import 가능한 형식
- **JSON**: 모바일 앱이 소비할 수 있는 형식
- **PDF**: 인쇄물 또는 오프라인 배포용

이렇게 4가지 형식이 모두 필요할 수 있다. 일반 블로거라도 마찬가지다. 레시피 블로그라면 HTML과 함께 인쇄용 PDF를 동시에 제공하고 싶을 것이다.

현재 Jekyll의 기본 기능으로는 각 포스트마다 별도의 마크다운 파일을 작성해야 한다. 즉, 내용을 중복 관리해야 한다는 뜻이다. 이는 나중에 수정할 때 정말 골칫거리가 된다.

## 실제 해결책: 플러그인 활용하기

다행히 Jekyll의 확장성은 뛰어나다. 커뮤니티가 만든 플러그인들이 이 문제를 해결할 수 있다. 내가 적용한 방법을 공유하겠다.

**첫 번째 방법: jekyll-feed와 커스텀 레이아웃 조합**

`_config.yml`에 여러 출력 형식을 정의할 수 있다:
```yaml
output_formats:
  - html
  - json
  - ics
```

그리고 각 포스트의 front matter에서 `output_formats`을 지정하면, Jekyll이 처리 과정에서 해당 형식들로 모두 생성하도록 하는 플러그인을 작성하는 것이다.

**두 번째 방법: GitHub Actions와의 연계**

더 우아한 방법은 GitHub Actions를 활용하는 것이다. 포스트가 push될 때 자동으로:
1. HTML은 기본대로 생성
2. 별도의 스크립트로 마크다운을 읽어 iCal 형식으로 변환
3. 또 다른 스크립트로 JSON 형식으로 변환

이렇게 하면 Jekyll 자체는 건드리지 않고도 여러 형식을 동시에 생성할 수 있다.

## 내가 선택한 현실적 해결책

결국 나는 jekyll-multiple-outputs라는 커뮤니티 플러그인과 직접 작성한 Ruby 스크립트를 결합했다. Front matter에 이렇게 작성하면:

```yaml
---
title: "2026년 2학기 개강일"
date: 2026-07-19
outputs: [html, ics]
---
```

Jekyll 빌드 프로세스 중에 후처리 단계에서 마크다운을 파싱해 iCal 형식으로 변환하는 방식이다. 약간의 학습곡선이 있지만, 일단 설정하면 이후로는 매우 편리하다.

또한 미리 정의된 Liquid 필터를 사용해 레이아웃 파일 내에서 조건부로 콘텐츠를 다르게 렌더링할 수도 있다. 예를 들어 PDF 생성 시에만 인쇄용 CSS를 적용하고, iCal 생성 시에만 이벤트 데이터를 특정 형식으로 출력하는 식이다.

여러 해 IT 경력을 쌓은 사람들도 이 부분에서 막혀있다. 하지만 한번 이해하고 나면, Jekyll의 진정한 유연성을 경험할 수 있다. 내 블로그는 이제 하나의 포스트로부터 4가지 형식을 동시에 생성하고 있으며, 학생들은 자신의 캘린더에 학사일정을 자동으로 추가할 수 있게 되었다.

지금 당신의 Jekyll 블로그에서 같은 문제를 겪고 있다면, 댓글로 당신의 구체적인 사용 사례를 공유해주기를 바란다. 함께 고민해 더 나은 해결책을 찾을 수 있을 것이다.
