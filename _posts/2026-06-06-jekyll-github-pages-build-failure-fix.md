## 서론: 퇴직 후 블로그를 시작하며 겪은 좌절감

저는 30년간 소프트웨어 개발자로 일하다가 작년에 은퇴했습니다. 시간이 남아돌자 그동안 하지 못했던 기술 블로그를 시작하기로 결심했고, Jekyll과 GitHub Pages를 선택했습니다. 워낙 유명한 조합이니 설치하면 자동으로 작동할 거라 생각했죠. 그러나 현실은 다았습니다. 푸시한 지 5분이 지났는데도 사이트가 업데이트되지 않았고, GitHub의 빨간 X 마크가 제 희망을 무너뜨렸습니다. 이 경험 속에서 얻은 교훈을 오늘 여러분과 공유하려 합니다.

## 가장 흔한 실패 원인: Gemfile과 의존성 충돌

처음 내가 범한 가장 큰 실수는 로컬 환경과 GitHub Pages 서버 환경의 Ruby 버전과 gem 의존성이 다를 수 있다는 점을 무시한 것입니다. 내 노트북에서는 Jekyll이 완벽하게 작동했지만, GitHub의 서버에서는 계속 빌드 실패 메시지가 나타났습니다.

해결책은 간단했습니다. 먼저 `Gemfile`을 정확히 구성하는 것이 중요합니다. GitHub Pages는 특정 버전의 gem들만 지원하므로, Jekyll 공식 문서에서 제공하는 템플릿을 따라야 합니다. 특히 `github-pages` gem을 직접 설치하면 GitHub 서버와 동일한 환경을 로컬에 구축할 수 있습니다. 저는 `bundle update`를 실행하고 `Gemfile.lock`을 깃에 커밋하니 문제가 해결되었습니다.

또 다른 흔한 원인은 플러그인 때문입니다. 아무리 멋진 플러그인이라도 GitHub Pages의 안전 모드에서 지원하지 않으면 빌드가 실패합니다. 저는 처음엔 Disqus 댓글 플러그인을 설치했다가 빌드 실패를 경험했고, 결국 공식 지원 플러그인만 사용하도록 변경했습니다.

## _config.yml의 숨겨진 함정들

두 번째로 겪은 문제는 설정 파일이었습니다. 많은 튜토리얼에서 제공하는 `_config.yml` 예제를 그대로 복사했는데, 특정 옵션들이 GitHub Pages와 호환되지 않았습니다. 예를 들어 `source`와 `destination` 경로를 임의로 설정하거나, 지원하지 않는 markdown 처리기를 지정하면 빌드가 실패합니다.

저는 GitHub Pages 공식 문서를 정독한 후 최소한의 필수 설정만 유지하기로 결정했습니다. 특히 `markdown: kramdown`은 필수이며, `theme`은 지원되는 테마만 사용해야 합니다. 저는 Chirpy 테마를 사용 중인데, 로컬에서는 완벽하게 작동했지만 GitHub 서버에서는 일부 기능이 작동하지 않아 공식 가이드를 재확인했습니다.

한 가지 알아낸 중요한 사실은 GitHub Pages가 특정 폴더와 파일명을 예약어로 지정한다는 것입니다. `.nojekyll` 파일 같은 것을 실수로 생성했다간 Jekyll 빌드 자체가 비활성화됩니다. 저는 실수로 이 파일을 커밋했고, 30분간 원인을 찾지 못했습니다.

## 디버깅 방법: Actions 탭과 로그 읽기

은퇴 후에 가장 다행스러운 점은 시간이 많다는 것입니다. 덕분에 GitHub Actions 로그를 자세히 분석할 수 있었습니다. GitHub 저장소의 Actions 탭에서 빌드 프로세스의 상세 로그를 확인할 수 있으며, 여기에 실패 원인이 모두 기록됩니다.

예를 들어 "Liquid Exception"은 템플릿 문법 오류를, "gem not found"는 의존성 문제를 나타냅니다. 저는 처음엔 이 로그를 무시했는데, 지금은 매번 푸시 후 Actions 탭을 확인하는 것을 습관화했습니다.

또한 로컬에서 `bundle exec jekyll build`를 실행하면 GitHub 서버의 빌드 과정을 거의 동일하게 재현할 수 있습니다. 저는 이 명령어를 실행한 후 `_site` 폴더를 확인하고 오류 메시지를 정독하기 시작했습니다. 이 방식이 가장 빠르고 효율적인 디버깅 방법입니다.

## 마지막 조언: 작은 것부터 시작하세요

30년의 개발 경력이 있어도 새로운 도구 앞에서는 초심자입니다. 저는 처음 너무 복잡한 구조로 블로그를 구성하려다 막혔습니다. 지금은 단순한 마크다운 파일과 기본 설정만으로 시작할 것을 권장합니다. 기본이 완벽하게 작동한 후에 차근차근 기능을 추가하는 것이 훨씬 안정적입니다.

GitHub Pages와 Jekyll의 조합은 정말 강력하고 자유로운 블로그 환경을 제공합니다. 초기 설정 단계는 혼란스럽겠지만, 한 번 해결하면 앞으로 안정적인 블로그 운영이 가능합니다. 지금 바로 Actions 탭의 빌드 로그를 확인하고, 오류 메시지 한 줄 한 줄을 읽으며 차근차근 해결해보세요.
