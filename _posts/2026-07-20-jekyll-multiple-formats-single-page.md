지난 5년간 대학을 정년퇴직하면서 생각해볼 기회가 있었습니다. 30년을 가르친 강의 자료들, 세미나 일정들, 학술 발표 기록들을 어떻게 정리하고 보관할지 말이죠. 그러다 GitHub Pages에 Jekyll 블로그를 시작했고, 결국 은퇴 후 개인 학술 웹사이트를 만들게 되었습니다. 

그런데 막상 시작하니 문제가 생겼습니다. 매 학기마다 올리는 세미나 공고를 HTML 형식으로도 보여주고, 동시에 학생들이 자신의 캘린더 앱(Google Calendar, Outlook 등)에 바로 추가할 수 있도록 **iCal 형식(`.ics` 파일)**으로도 제공하고 싶었던 겁니다. 그리고 PDF로도 인쇄본을 준비하고 싶었고요. 

초보자인 저는 하나의 마크다운 파일에서 이 모든 포맷을 동시에 생성할 수 있으리라 기대했습니다. 하지만 현실은 달랐습니다.

## 처음 맞닥뜨린 문제: 하나의 파일, 하나의 포맷만 가능하다

Jekyll의 기본 구조를 이해하면서 깨달은 첫 번째 한계가 바로 이것입니다. 일반적으로 Jekyll에서 마크다운 파일을 처리할 때, 하나의 소스 파일은 하나의 출력 포맷만 생성합니다. 

예를 들어 `2026-07-20-seminar.md` 파일을 작성하면, 기본 레이아웃에 따라 `index.html` 또는 해당 경로의 HTML 파일만 생성됩니다. iCal 포맷이나 PDF 포맷을 동시에 원한다면? 같은 내용의 파일을 여러 번 복사하고, 각각에 다른 레이아웃을 적용해야 했습니다. 

이는 유지보수의 악몽이었습니다. 나중에 세미나 내용을 수정하면 모든 파일을 일일이 고쳐야 했거든요. 대학 시절 학생 논문을 관리하면서도 비슷한 경험을 했는데, 이번엔 내 자신이 같은 실수를 저지르고 있었습니다.

## Jekyll 레이아웃 개선 제안: 하나의 포스트, 다중 포맷 출력

2015년 GitHub의 Jekyll 공식 이슈(#3041)에서 이 문제를 제기한 개발자가 있었습니다. "하나의 페이지/포스트에서 여러 출력 포맷을 생성할 수 있으면 좋겠다"는 제안 말이죠. 

실제로 많은 개인 블로거, 교육자, 콘텐츠 크리에이터들이 비슷한 필요성을 느끼고 있었습니다. 예컨대:

- **학술 블로그**: HTML 페이지 + 인용 메타데이터(BibTeX 형식)
- **이벤트 공고**: 웹페이지 + iCal 파일
- **뉴스레터**: HTML 버전 + 텍스트 버전 + PDF
- **포트폴리오**: 웹 버전 + 인쇄용 PDF

이런 니즈를 충족시키기 위해 제안된 해결책은 **레이아웃 시스템을 확장하여 하나의 포스트에서 여러 확장자(`.html`, `.ics`, `.xml` 등)를 가진 파일들을 동시에 생성**하는 것이었습니다.

## 실전 해결책: 커스텀 플러그인으로 문제 해결하기

결국 저는 두 가지 실용적인 방법을 찾아 적용했습니다.

**방법 1: 커스텀 플러그인 작성**

Jekyll의 generator를 이용해 커스텀 플러그인을 만드는 것입니다. 하나의 포스트를 읽어들인 후, 여러 레이아웃을 적용하여 각각 다른 확장자로 출력하는 방식이죠. 예를 들어, `_plugins/multi_format_generator.rb` 파일을 작성하여:

```ruby
Jekyll::Hooks.register :posts, :post_init do |post|
  # .md 파일을 읽고 .html, .ics, .pdf로 각각 생성
end
```

이 방식은 강력하지만, Ruby에 대한 이해가 필요합니다. 제 나이대(70대 초반)의 개발자라면 처음엔 낯설 수 있겠죠.

**방법 2: 다중 output 설정 활용**

Jekyll의 `_config.yml`에서 각 포스트마다 여러 output을 정의하는 방법입니다:

```yaml
defaults:
  - scope:
      path: "_posts/seminars"
    values:
      output:
        - html
        - ics
        - pdf
```

그리고 각각의 레이아웃 파일(`layout-default.html`, `layout-ical.html` 등)을 준비해두는 겁니다.

**방법 3: 빌드 후 처리 스크립트**

저는 결국 가장 실용적인 방식을 택했습니다. Jekyll이 HTML을 먼저 생성한 후, Python이나 Bash 스크립트로 HTML을 파싱하여 iCal 포맷으로 변환하는 방식입니다. 간단하고, 기술 수준이 낮아도 이해하기 쉬웠거든요.

## 현재 상황과 미래 전망

흥미롭게도, 이 이슈는 제시된 지 10년이 넘었음에도 Jekyll의 공식 기능으로는 채택되지 않았습니다. 대신 커뮤니티에서 다양한 플러그인과 우회 방법들이 개발되어 왔습니다. 이는 한 가지를 시사합니다: **복잡한 요구사항에는 오픈소스의 유연성이 필수**라는 점 말이죠.

제 경험상, 은퇴자들이 개인 웹사이트를 만들 때 이 문제에 자주 마주칩니다. 특히 학술 자료, 이벤트 정보, 개인 포트폴리오 등을 관리할 때 말입니다. 단순한 블로그로 시작했다가, 자신의 콘텐츠를 다양한 형식으로 제공하고 싶어질 때 바로 이 한계를 느끼게 됩니다.

지금 혹시 당신도 비슷한 상황에 처해 있다면, 처음부터 이를 염두에 두고 설계하는 것이 좋습니다. 단순 HTML 블로그가 아니라 다중 포맷 출력 시스템으로요. 제가 겪은 시행착오들이 당신의 웹사이트 구축 여정에 조금이나마 도움이 되길 바랍니다.

혹시 당신도 Jekyll로 여러 포맷을 동시에 생성하려던 경험이 있으신가요? 댓글로 당신의 해결 방법을 나눠주시면, 같은 고민을 하는 다른 독자들에게 큰 도움이 될 것 같습니다.
