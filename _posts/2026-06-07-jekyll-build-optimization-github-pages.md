## 오래된 컴퓨터에서 배운 소중한 교훈

대학을 정년퇴직한 후 취미로 시작한 Jekyll 블로그, 정말 매력적이었습니다. 마크다운으로 글을 쓰면 자동으로 정적 사이트가 생성되고, GitHub Pages에서 무료로 호스팅까지 되니까요. 그런데 포스팅을 50개, 100개 정도 쌓다 보니 문제가 생겼습니다. 로컬에서 `jekyll serve` 명령어를 실행할 때마다 5분, 10분씩 기다려야 했거든요. 나이 든 사람에게 이 기다림은 정말 고역이었습니다.

그래서 저는 Jekyll의 공식 문서를 처음부터 끝까지 정독했고, 커뮤니티 포럼에도 자주 방문했습니다. 그 과정에서 발견한 빌드 최적화 기법들을 실제로 적용해보니, 정말 놀라운 변화가 일어났습니다. 처음엔 600초 걸리던 빌드가 60초 안에 완료되기 시작했던 것입니다. 오늘은 그 경험담을 여러분과 나누고 싶습니다.

## 증분 빌드(Incremental Build)와 드래프트 모드 활용

Jekyll의 가장 강력한 무기는 `--incremental` 플래그입니다. 이 옵션을 사용하면 Jekyll은 변경된 파일만 다시 빌드하고 나머지는 그대로 유지합니다. 제 경험상 이것만으로도 빌드 시간을 절반 이상 줄일 수 있었습니다.

`_config.yml` 파일에 다음과 같은 설정을 추가하세요:

```yaml
incremental: true
regenerate: true
```

그리고 터미널에서 `jekyll serve --incremental` 또는 `jekyll serve -I` 명령어를 사용하세요. 저는 이 방법으로 로컬 테스트 시간을 대폭 단축할 수 있었습니다.

추가로, 개발 단계에서는 드래프트 포스팅도 제외하는 것이 좋습니다. `_drafts` 폴더에 임시 글들을 보관했다면, 빌드 시 이들을 무시하도록 설정할 수 있습니다:

```yaml
exclude:
  - _drafts
  - .git
  - node_modules
  - vendor
```

## 플러그인 최소화와 불필요한 리소스 정리

저는 처음엔 SEO 플러그인, 사이트맵 플러그인, 피드 플러그인까지 마구잡이로 설치했습니다. 하지만 각 플러그인마다 빌드 시간이 추가로 소모된다는 것을 알게 됐습니다. GitHub Pages에서는 보안상 허용되는 플러그인이 제한적이므로, 꼭 필요한 것만 유지하는 것이 현명합니다.

Chirpy 테마의 경우 이미 대부분의 기능이 포함되어 있으므로, 추가 플러그인은 신중하게 선택해야 합니다. 제가 권장하는 최소 플러그인 세트는 다음과 같습니다:

- `jekyll-paginate-v2`: 페이지네이션
- `jekyll-feed`: RSS 피드 생성
- `jekyll-sitemap`: 사이트맵 자동 생성

불필요한 이미지들도 정리했습니다. 고해상도 사진들이 `assets` 폴더에 쌓여 있으면 빌드할 때마다 모두 처리해야 합니다. ImageOptim이나 TinyPNG 같은 도구로 이미지를 압축하고, 정말 필요 없는 것들은 과감히 삭제했습니다.

## GitHub Actions를 통한 자동 배포 최적화

GitHub Pages의 자동 배포 과정도 최적화할 여지가 있습니다. 저는 처음엔 매번 로컬에서 빌드한 후 `_site` 폴더를 수동으로 커밋했는데, 이는 비효율적이었습니다.

대신 GitHub Actions 워크플로우를 설정해서 푸시할 때마다 자동으로 빌드하고 배포하도록 했습니다. 이 방식이면 로컬 빌드 시간은 짧게 유지하면서도 최종 배포는 GitHub의 강력한 서버에서 처리됩니다.

`.github/workflows/pages.yml` 파일에 다음과 같은 설정을 추가하면 됩니다:

```yaml
- name: Build with Jekyll
  uses: actions/jekyll-build-pages@v1
  with:
    source: ./
    destination: ./_site
```

이 과정에서 `--profile` 옵션을 활용하면 각 단계별 소요 시간을 파악할 수 있어, 추가적인 최적화 지점을 찾는 데 도움이 됩니다.

무엇보다 중요한 것은, 이런 작업들이 제 포스팅에 더욱 집중할 수 있는 환경을 만들어주었다는 점입니다. 기다림 없이 쓴 글을 즉시 확인하고, 수정하고, 배포할 수 있다는 것이 얼마나 소중한지 모릅니다.
