## 내가 마주친 끔찍한 에러 메시지

은퇴한 지 3년차, 취미로 시작한 기술 블로그가 어느날 갑자기 배포되지 않았습니다. GitHub Actions 로그를 들어가 보니 "Build Failed" 메시지만 반복되더군요. 처음엔 최신 포스트의 마크다운 문법이 잘못되었나 싶어 다시 작성해봤지만, 문제는 전혀 다른 곳에 있었습니다. 정확히는 Jekyll의 빌드 캐시였습니다.

지난 10년간 개발자로 일하면서 가장 답답했던 경험 중 하나는 바로 캐시 문제입니다. 로컬 환경에서는 멀쩡하게 작동하는데 GitHub Pages에 올리면 톡 튀는 CSS, 반영되지 않는 설정들. 이 현상은 제가 은퇴 후 블로그를 시작하면서도 똑같이 반복되었습니다.

## Jekyll 캐시가 깨지는 구체적인 상황들

Jekyll은 빌드 속도를 높이기 위해 `.jekyll-cache` 폴더에 중간 결과물들을 저장합니다. 정상적으로 작동할 때는 좋지만, 문제가 생기면 이 캐시 때문에 며칠을 고민해야 합니다.

제가 경험한 캐시 문제는 주로 세 가지 상황에서 발생했습니다. 첫째, Gemfile을 수정하고 로컬에서 `bundle install`을 실행했는데, GitHub Actions 환경에는 여전히 이전 버전의 플러그인 정보가 캐시되어 있던 경우입니다. 둘째, `_config.yml` 파일의 플러그인 목록을 추가했을 때, 로컬 빌드는 성공했는데 GitHub의 CI/CD 파이프라인에서는 실패하는 경우였습니다. 셋째, 테마를 업데이트한 후 SCSS 변수가 제대로 컴파일되지 않았던 경험입니다.

이 문제들의 공통점은 모두 '로컬과 원격 환경의 캐시 불일치'였습니다. 내 맥북에서는 최신 캐시로 빌드되지만, GitHub의 서버에는 여전히 구형 캐시 데이터가 남아있는 것이죠.

## 실전 해결책: 캐시를 완전히 제거하는 방법

가장 직관적이고 효과적인 해결책은 캐시를 완전히 비우는 것입니다. 제가 10년 경력으로도 처음엔 놓쳤던 부분인데, 이는 여러 단계로 진행됩니다.

**첫 번째: 로컬 환경 정리**

로컬 개발 환경에서는 터미널을 열고 다음 명령어들을 순서대로 실행합니다.

```bash
rm -rf .jekyll-cache
rm -rf _site
bundle clean
bundle install
```

이 네 줄이 마법의 주문입니다. `.jekyll-cache` 폴더를 삭제하고, 생성된 정적 파일들을 모두 제거한 뒤, Bundler 캐시도 정리하고 다시 설치합니다.

**두 번째: Git에서 캐시 폴더 제외 확인**

`.gitignore` 파일을 열어서 다음 항목들이 포함되어 있는지 확인해야 합니다:

```
.jekyll-cache/
_site/
.bundle/
vendor/
```

이 폴더들이 Git 저장소에 커밋되지 않도록 하는 것이 중요합니다. 만약 이미 커밋되었다면, 깃 히스토리에서도 제거해야 합니다.

**세 번째: GitHub Actions 워크플로우 최적화**

`.github/workflows` 디렉토리의 배포 파일을 수정합니다. 제 경우 `jekyll.yml` 파일을 다음과 같이 구성했습니다:

```yaml
- name: Clear cache
  run: rm -rf .jekyll-cache _site
  
- name: Build with Jekyll
  uses: actions/jekyll-build-pages@v1
```

캐시 삭제 단계를 명시적으로 추가하면, 매 배포마다 깨끗한 상태에서 빌드를 시작합니다.

## 내가 배운 예방법

이제는 이 문제가 반복되지 않도록 몇 가지 습관을 들였습니다. 테마나 플러그인을 업데이트할 때마다 먼저 로컬에서 캐시를 삭제하고 빌드 결과를 확인하는 것입니다. 또한 `Gemfile.lock` 파일을 Git에 커밋해서 로컬과 GitHub의 의존성 버전이 일치하도록 관리합니다.

은퇴 후 취미로 시작한 블로그였지만, 이 과정에서 얻은 기술적 경험은 정말 값집니다. 개발자 시절과 달리 이제는 천천히, 그리고 더 깊이 있게 한 가지 문제를 파고들 수 있게 되었으니까요.

여러분도 Jekyll 블로그를 운영하면서 갑작스러운 배포 실패로 답답해하신다면, 가장 먼저 캐시를 의심해보세요. 많은 경우 이 간단한 해결책으로 문제가 금세 해결될 것입니다. 지금 바로 로컬 저장소에서 `.jekyll-cache` 폴더를 확인하고 정리해보시기 바랍니다!
