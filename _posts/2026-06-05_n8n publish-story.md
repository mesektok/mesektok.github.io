# n8n Publish와 Published 버튼의 숨은 이야기

67세 교수가 자동화를 배우다 마주친 작은 혼란, 그런데 알고 보니 꽤 깊은 이야기였습니다.

---

## 무엇인가 (What)

n8n 워크플로우 편집 화면 우상단에는 버튼이 하나 있습니다.

처음엔 그냥 "켜는 버튼"이라고 생각했습니다. 그런데 어느 날 보니 색깔이 달랐습니다.

```
🟡 노란불 → Publish 버튼
🟢 초록불 → Published 상태
```

같은 자리, 다른 의미였습니다.

### 🟡 노란불: Publish 버튼

워크플로우를 수정한 뒤 **아직 저장하지 않은 변경사항**이 있을 때 나타납니다.
드롭다운을 클릭하면 두 가지 선택지가 보입니다:

- **Publish** → 변경사항 저장 + 활성화
- **Unpublish** → 워크플로우 비활성화

즉, 노란불은 *"어떻게 할까요?"* 라고 묻는 상태입니다.

### 🟢 초록불: Published 상태

변경사항이 모두 저장되고 **워크플로우가 완전히 활성화**된 상태입니다.
드롭다운도 없고, 선택할 것도 없습니다.
그냥 **켜져 있는 것**입니다.

---

## 왜인가 (Why)

왜 n8n은 이걸 두 가지로 나눴을까요?

자동화 도구에서 가장 위험한 순간은 **수정 중인 워크플로우가 실수로 실행되는 것**입니다.

예를 들어 API 주소를 바꾸다가 절반만 수정된 상태로 스케줄이 실행되면 오류가 납니다.
그래서 n8n은 이렇게 설계했습니다:

```
수정 중 → 🟡 노란불 (임시 저장 상태)
확정 후 → 🟢 초록불 (완전 활성화)
```

이것은 마치 문서 작업에서 **임시저장**과 **최종저장**의 차이와 같습니다.

---

## 어떻게 쓰는가 (How)

### 워크플로우를 처음 만들 때

```
노드 구성 완료
    ↓
🟡 노란불 상태 확인
    ↓
Publish 클릭
    ↓
🟢 초록불 = 자동 실행 시작
```

### 기존 워크플로우를 수정할 때

```
노드 수정
    ↓
자동으로 🟡 노란불로 변경
    ↓
테스트 완료 후 Publish 클릭
    ↓
🟢 초록불 복귀
```

### 잠깐 멈추고 싶을 때

```
🟢 초록불 클릭
    ↓
🟡 노란불로 변경
    ↓
Unpublish 선택
    ↓
⚫ 비활성화 = 자동 실행 중지
```

## 오늘의 성찰

처음에 저는 이 버튼이 그냥 "켜고 끄는 스위치"라고 생각했습니다.

그런데 색깔 하나에도 이유가 있었습니다.
노란불은 경고였고, 초록불은 확인이었습니다.

자동화 도구를 잘 쓰려면 버튼 하나의 의미도 정확히 알아야 합니다.
