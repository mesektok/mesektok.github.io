대학에서 40년간 컴퓨터공학을 가르치다 지난해 은퇴한 나는, 요즘 개인 기술 블로그를 운영하며 여유로운 시간을 보내고 있습니다. 그런데 최근 GitHub Pages에 블로그를 구축하면서 예상치 못한 문제에 직면했습니다. 포스트를 작성할 때마다 배포가 3~4분씩 걸리는 것이었죠. 이게 도대체 뭐 하는 거야? 싶어서 문제를 파헤쳐본 결과, 간단한 Jekyll 설정 조정으로 배포 속도를 10배 가까이 단축할 수 있었습니다. 지난 30년 시스템 최적화 경험을 바탕으로, 같은 고민을 하는 분들을 위해 그 노하우를 공유하려고 합니다.

## Jekyll의 _config.yml 파일 최적화

가장 먼저 손을 봐야 할 부분은 Jekyll 설정 파일입니다. 은퇴하고 처음 블로그를 시작할 때, 나는 Chirpy 테마를 설치하고 기본 설정값을 그대로 사용했습니다. 하지만 이것이 실수였습니다. Jekyll의 기본 설정은 매우 보수적으로 되어 있어서 불필요한 작업까지 모두 수행하거든요.

가장 효과적인 최적화는 `_config.yml`에서 `exclude` 항목을 확장하는 것입니다. 빌드 과정에서 굳이 처리할 필요가 없는 파일들을 미리 제외시키는 방식이죠. 저는 다음과 같이 설정했습니다:

```yaml
exclude:
  - '*.gemfile'
  - 'Gemfile.lock'
  - 'node_modules/'
  - 'vendor/'
  - '.git/'
  - '.github/'
  - 'docs/'
  - '.gitignore'
```

이렇게 설정하니 빌드 시간이 즉시 30% 단축되었습니다. 컴퓨터 구조론을 수십 년 가르쳐온 경험상, 불필요한 I/O 작업을 줄이는 것만 해도 큰 성능 향상을 이룰 수 있다는 사실을 다시 한번 확인했습니다.

## GitHub Actions 캐싱 활용하기

GitHub Pages 배포는 자동으로 GitHub Actions를 사용합니다. 그리고 여기서 놀라운 최적화 기법을 발견했습니다. 바로 Actions 캐싱입니다.

`.github/workflows` 디렉토리에 있는 Jekyll 빌드 워크플로우를 직접 수정할 수는 없지만, Chirpy 테마를 사용하는 경우라면 커스텀 actions 파일을 생성할 수 있습니다. 저는 다음과 같은 설정을 추가했습니다:

```yaml
- name: Cache gems
  uses: actions/cache@v3
  with:
    path: vendor/bundle
    key: ${{ runner.os }}-gems-${{ hashFiles('**/Gemfile.lock') }}
    restore-keys: |
      ${{ runner.os }}-gems-
```

이 설정은 Ruby gem 의존성을 캐싱하여 다음 배포 때 다시 다운로드할 필요가 없게 만듭니다. 처음 배포는 여전히 2분 정도 걸리지만, 그 이후부터는 겨우 10~15초 만에 배포가 완료됩니다. 은퇴 후 배우기 시작한 Ruby 생태계에서 이런 영리한 기법을 발견했을 때의 희열은 이루 말할 수 없었습니다.

## 로컬 빌드 성능 향상과 테스트

마지막이지만 가장 중요한 팁은 로컬 환경에서의 빌드 최적화입니다. 실제로 배포하기 전에 로컬에서 테스트하는 습관은 전체 프로세스 시간을 절약합니다.

로컬에서 빌드할 때는 다음 명령어를 사용합니다:

```bash
bundle exec jekyll serve --incremental --strict_front_matter
```

`--incremental` 옵션은 변경된 파일만 다시 빌드하므로 수정 후 몇 초 안에 결과를 확인할 수 있습니다. 이는 개발 워크플로우를 극적으로 개선합니다.

또한 `Gemfile`에서 불필요한 플러그인을 제거하는 것도 중요합니다. Chirpy 테마에는 많은 플러그인이 포함되어 있는데, 실제로 사용하지 않는 것들이 있을 수 있거든요. 저는 `jekyll-analytics`와 같이 사용하지 않는 플러그인을 주석 처리하니 빌드 시간이 추가로 20% 단축되었습니다.

지난 몇 개월간 이런 최적화들을 적용하면서, 결국 내 GitHub Pages 배포 시간은 초기의 4분에서 현재 30초 정도로 단축되었습니다. 대학 시절 학생들에게 "작은 최적화가 모여서 큰 성능 향상을 만든다"고 강의하던 내 말이 이제야 실감이 됩니다.
