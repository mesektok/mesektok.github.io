지난겨울, 대학에서 30년을 가르친 후 은퇴한 나는 학교 선배들과의 정기 모임을 온라인으로 관리하기로 결심했습니다. Jekyll 블로그로 행사 소식을 전하되, 바쁜 선후배들을 위해 자동으로 캘린더 파일(iCal)도 함께 제공하고 싶었습니다. 그런데 문제가 생겼습니다. Jekyll은 한 페이지에서 하나의 형식만 만들어낸다는 것이었습니다.

## 한 포스트, 여러 형식의 딜레마

처음엔 간단하다고 생각했습니다. 행사 정보를 작성하면 HTML 페이지도 나오고, iCal 파일도 나오면 되지 않을까요? 하지만 Jekyll의 기본 구조는 그렇게 작동하지 않습니다. 한 개의 마크다운 파일은 하나의 출력 형식만 생성합니다. 

저는 당시 두 가지 우회 방법을 시도했습니다. 첫째는 행사마다 별도의 마크다운 파일을 두 개씩 만드는 것이었습니다. 하나는 HTML용, 하나는 iCal용. 하지만 이렇게 하면 같은 내용을 두 번 관리해야 하고, 수정할 때마다 두 파일을 모두 열어야 했습니다. 실수로 한쪽만 업데이트하면 정보가 엇갈리는 황당한 일도 발생했습니다.

둘째 방법은 플러그인을 직접 만드는 것이었습니다. 그 과정은 매우 복잡했고, 무엇보다 GitHub Pages 환경에서는 커스텀 플러그인을 실행할 수 없다는 한계가 있었습니다.

## 해결책: 레이아웃의 다중 확장자 지원

GitHub Jekyll의 공식 이슈 #3041을 발견했을 때, 제 문제가 나 혼자만의 것이 아니라는 사실에 위안이 되었습니다. 많은 사용자들이 같은 어려움을 겪고 있었으니까요.

이 이슈에서 제안하는 해결책은 **레이아웃에 여러 확장자를 할당**하는 것입니다. 예를 들어, 하나의 포스트에 대해 `.html` 레이아웃과 `.ics` 레이아웃을 동시에 적용하면, 같은 콘텐츠에서 HTML과 iCal 파일이 함께 생성되는 방식입니다.

실제 구현은 이렇게 이루어집니다. 포스트의 front matter에서 다중 레이아웃을 지정하거나, 또는 `_config.yml`에서 특정 콜렉션에 대해 기본 레이아웃들을 설정하는 방식입니다. 그러면 빌드 과정에서 Jekyll이 자동으로 각 포스트마다 여러 형식의 파일을 생성합니다.

## 현실적인 대안과 향후 전망

현재는 아직 Jekyll 코어에 이 기능이 완전히 통합되지 않았습니다. 다행히 몇 가지 실용적인 대안들이 있습니다.

**첫 번째 방법**은 Jekyll 플러그인 생태계를 활용하는 것입니다. `jekyll-feed` 같은 플러그인들이 이미 다중 형식 생성을 부분적으로 지원하고 있습니다. 데이터 파일 방식으로 이벤트 정보를 관리하고, 각 형식의 레이아웃을 따로 만들어서 동일한 데이터로부터 여러 포맷을 렌더링하는 접근도 가능합니다.

**두 번째 방법**은 빌드 후 처리(post-processing) 스크립트를 작성하는 것입니다. Jekyll이 HTML을 생성한 후, 추가 스크립트가 그 파일을 파싱하여 iCal 형식으로 변환합니다. 복잡해 보이지만, 실제로는 Python이나 Ruby로 간단한 스크립트를 만들 수 있습니다.

**세 번째 방법**은 저희가 실제로 채택한 것으로, API 기반 접근입니다. Jekyll 블로그 자체는 HTML만 생성하되, 별도의 JSON 데이터를 만들어두고, 정적 생성기나 클라이언트 사이드 자바스크립트로 iCal을 동적 생성하는 방식입니다. GitHub Pages 환경에서도 완벽하게 작동합니다.

## 은퇴인의 조언

저 같은 나이 또래 블로거들이 Jekyll을 선택하는 이유는 간단하고 안정적이기 때문입니다. 하지만 한 가지 콘텐츠를 여러 형식으로 공유하고 싶을 때는 좀 더 창의적인 접근이 필요합니다. 

제 경험상 가장 중요한 것은 **데이터와 표현의 분리**입니다. 콘텐츠는 한 곳에만 관리하고, 표현 형식만 여러 개 만드는 방식으로 생각하면 복잡함이 크게 줄어듭니다.

오늘 이 글을 읽은 분 중 행사 안내, 제품 정보, 학사일정 같은 것을 여러 형식으로 배포하고 싶으신 분이라면, 댓글로 당신의 상황을 공유해주세요. 우리 함께 가장 적합한 해결책을 찾아보겠습니다.
