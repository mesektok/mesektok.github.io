### 🎙️ 오늘의 팟캐스트
Jekyll 블로그 빌드가 자꾸 멈춘다면? 이미지 변환 작업 타임아웃 해결법

&nbsp;

### 📌 에피소드 주요 내용
- Jekyll 빌드 실패의 원인은 고해상도 이미지의 자동 변환 작업이 30분 타임아웃을 초과하기 때문
- 이미지 압축, 플러그인 설정 최적화, GitHub Actions 캐싱 강화의 세 가지 해결책 제시
- 점진적인 업데이트와 사전 최적화로 안정적인 블로그 운영 가능

### 🎧 전체 대본
**지혜:** 안녕하세요! 오늘은 Jekyll 블로그를 운영하시는 분들이라면 정말 공감할 만한 주제를 가져왔어요. 노교수님, 안녕하세요!

**박교수:** 안녕하네. 오늘 주제가 내 경험담과 딱 맞아떨어진다네. 은퇴 후 블로그를 시작했는데, 처음엔 텍스트만 올릴 땐 멀쩡하더군. 그런데 학생들이 고화질 이미지를 원하기 시작하면서 악몽이 시작됐다네. 매번 빌드할 때마다 GitHub Actions에서 몇 분을 버티다가 돌연 실패 메시지를 내뱉더군.

**지혜:** 아, 그럼 처음엔 원인을 모르셨던 거네요?

**박교수:** 그렇지. 마크다운 문법이 잘못된 줄 알고 한 줄 한 줄 점검했다네. 새로운 기술이 낯설어서 말이야. 하지만 GitHub 이슈 게시판을 찾아보니 같은 증상을 호소하는 사람들이 수십 명이나 있었다. 결국 알아낸 게 Jekyll의 이미지 변환 작업이 타임아웃되는 거였어. WEBP 형식 변환, 썸네일 생성, 해상도 조정 같은 복잡한 이미지 처리가 30분 제한 시간을 초과하는 거였단 말이지.

**지혜:** 아, 그래서 빌드가 실패했던 거군요! 교수님의 경우엔 어떤 게 문제였어요?

**박교수:** 내 경우 학술 자료 특성상 고해상도 스캔본이 무더기였어. 각 이미지가 5~10MB를 넘었으니까. 그 외에도 플러그인 의존성 문제, 캐시 문제, Ruby 버전 호환성 같은 작은 실수들이 쌓여 있었네. 마치 학생들 논문 검수할 때처럼 말이야.

**지혜:** 그럼 어떻게 해결하셨어요?

**박교수:** 세 가지 방법을 썼어. 첫째, 빌드 전에 이미지 압축 도구로 파일 크기를 줄였다. 대학원 시절 데이터 정리 습관이 도움됐지. 둘째, Jekyll 설정 파일에서 불필요한 이미지 변환 플러그인을 비활성화했어. 그러니 빌드 시간이 20분대에서 5분 이내로 단축되더군. 셋째는 GitHub Actions 워크플로우 파일을 수정해서 캐싱을 강화했지. 이게 가장 효과적이었어.

**지혜:** 와, 정말 극적인 개선이네요! 지금은 어떻게 운영하세요?

**박교수:** 요즘은 월 30~50개 포스팅을 하는데 빌드 실패가 거의 없다네. 포스팅 전에 이미지를 반드시 최적화하고, 불필요한 플러그인은 과감히 제거했으며, 점진적인 업데이트를 선호한다네. 처음부터 완벽하게 설정하려다 보면 오히려 복잡해진다는 걸 깨달았어. 차라리 심플하게 시작해서 문제가 생길 때마다 해결하는 게 훨씬 현명하지.

**지혜:** 정말 실용적인 조언이 많네요! Jekyll 빌드로 고민 중인 분들이라면 꼭 도움이 될 것 같아요. 더 자세한 내용은 블로그 원문에서 확인하실 수 있어요!
