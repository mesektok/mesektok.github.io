얼마 전 은퇴 후 취미로 시작한 기술 블로그 운영 중에 이상한 일을 겪었습니다. GitHub Pages에 포스트를 올릴 때마다 빌드 과정에서 멈춰버리는 현상이었는데, 처음엔 네트워크 문제인 줄 알았습니다. 한참을 헤매다 문제의 원인을 찾아냈고, 이번에는 같은 어려움을 겪을 분들을 위해 경험을 나누고자 합니다.

## 빌드가 무한 대기하는 이유

Jekyll 또는 Gatsby 기반의 정적 사이트 생성기에서 이미지를 처리할 때, 시스템이 자동으로 이미지 최적화 작업을 수행합니다. 특히 Chirpy 테마를 사용하는 경우, 포스트에 삽입된 이미지들을 자동으로 변환하고 압축하는 기능이 활성화되어 있습니다. 

문제는 이 작업 큐(Job Queue)가 제대로 처리되지 않을 때 발생합니다. 저의 경우 하루에 3~4개의 포스트를 일괄 업로드했는데, 이미지 변환 작업이 쌓여서 제대로 진행되지 않았습니다. 시스템 로그를 자세히 살펴보니 "running jobs" 항목에서 계속 대기 중인 상태가 유지되고 있었습니다.

이는 특히 고해상도 이미지를 많이 사용하거나, 여러 형식(PNG, JPEG, WebP 등)으로 변환해야 할 때 더욱 심해집니다. 시니어 개발자들은 과거 경험상 빌드 도구의 성능을 과신하는 경향이 있는데, 현대의 이미지 처리는 생각보다 리소스를 많이 소비합니다.

## 근본적인 문제 파악하기

GitHub의 공식 이슈 트래커를 살펴보면, 이 문제는 여러 사용자가 보고한 흔한 사례입니다. 특히 Jekyll Chirpy 테마의 경우, 빌드 프로세스 중 이미지 변환 작업이 병렬로 처리되지 않아서 대기 시간이 늘어나는 경향을 보입니다.

저는 GitHub Actions의 로그를 자세히 확인하면서 다음과 같은 사실을 알게 되었습니다:

**첫째**, 이미지 변환 작업은 순차적으로 처리됩니다. 포스트마다 수십 개의 이미지가 있다면, 그것들을 하나씩 처리해야 합니다.

**둘째**, 서버의 리소스 제약이 있습니다. GitHub Actions의 무료 플랜은 할당된 CPU와 메모리에 제한이 있으며, 이미지 처리 같은 무거운 작업은 이 제한에 쉽게 걸립니다.

**셋째**, 캐시 메커니즘이 제대로 작동하지 않을 수 있습니다. 이전 빌드의 캐시가 유효하지 않으면, 매번 처음부터 이미지를 재처리해야 합니다.

제 경우, 한 포스트에 15개의 고해상도 이미지가 있었고, 4개의 다른 형식으로 변환하도록 설정되어 있었습니다. 단순 계산으로 60개의 이미지 변환 작업이 필요했던 것입니다.

## 실제 해결 방법과 예방책

저는 여러 가지 방법을 시도해봤습니다. 가장 효과적이었던 것들을 소개하겠습니다.

**첫 번째 방법**은 이미지 사전 처리입니다. 블로그에 업로드하기 전에 이미지 편집 소프트웨어에서 미리 최적화를 진행했습니다. 고해상도 사진의 경우 800x600 정도로 리사이징하고, 품질을 85% 수준으로 낮춰 파일 크기를 줄였습니다. 이렇게 하면 블로그의 빌드 속도뿐 아니라 로딩 속도도 개선됩니다.

**두 번째 방법**은 포스트 업로드 분산입니다. 한 번에 여러 포스트를 올리지 말고, 한두 개씩 나눠서 올렸습니다. 이렇게 하면 각 빌드 프로세스가 충분한 리소스를 할당받을 수 있습니다.

**세 번째 방법**은 Jekyll 설정 파일(`_config.yml`)을 직접 수정하는 것입니다. 이미지 변환 작업의 타임아웃 설정을 늘리거나, 병렬 처리 옵션을 활성화할 수 있습니다. 특히 GitHub Actions의 워크플로우 파일에서 타임아웃 시간을 기본 60분에서 120분으로 설정하는 것도 도움이 됩니다.

마지막으로, 혹시 프로젝트의 `node_modules` 폴더나 캐시가 손상되었을 가능성도 확인해볼 필요가 있습니다. GitHub Actions 대시보드에서 빌드 캐시를 초기화하고 다시 시도해보는 것도 효과적인 방법입니다.

저는 이 모든 방법을 종합적으로 적용한 후, 빌드 시간을 30분에서 7분으로 단축할 수 있었습니다. 블로그 운영 초반에 겪는 이러한 기술적 문제들은 사실 디버깅과 최적화의 좋은 기회입니다.

혹시 당신도 Jekyll 블로그의 빌드 지연으로 고민하고 있다면, 위의 방법들을 차례로 시도해보고 GitHub 공식 이슈 페이지에서 본인과 유사한 사례가 있는지 확인해보시기 바랍니다. 기술 커뮤니티의 경험과 지혜는 이런 순간에 가장 귀한 자산입니다.
