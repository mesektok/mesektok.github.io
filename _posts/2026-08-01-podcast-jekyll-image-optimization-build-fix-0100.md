### 🎙️ 오늘의 팟캐스트
Jekyll 블로그 빌드가 자꾸 멈춘다면? 이미지 변환 작업 최적화 가이드

&nbsp;

### 📌 에피소드 주요 내용
- Jekyll 블로그 빌드가 이미지 변환 작업에서 멈추는 문제의 원인은 고해상도 이미지의 대량 처리와 제한된 GitHub Actions 리소스
- 이미지 압축, 설정 파일 조정, 로컬 빌드 검증의 세 가지 단계적 해결 방법으로 빌드 시간을 크게 단축할 수 있음
- 가장 효과적인 첫 단계는 업로드 전 이미지 압축으로 파일 크기를 5MB에서 300~500KB로 줄이는 것

### 🎧 전체 대본
**지혜:** 안녕하세요, 팟캐스트 <기술 이야기>입니다. 오늘은 특별히 노교수님을 모셨어요. 교수님, 반갑습니다!

**박교수:** 감사합니다. 반갑네요. 저도 블로그를 운영하면서 여러 문제를 겪었는데, 오늘 그 경험을 나눌 수 있어서 기쁩니다.

**지혜:** 네! 교수님이 Jekyll 블로그를 시작하셨다고 들었는데, 어떤 계기였어요?

**박교수:** 직장을 떠난 후 그동안 공부했던 기술 지식을 누군가와 공유하고 싶었어요. GitHub Pages는 비용도 없고 마크다운으로 편하게 글을 쓸 수 있어서 매력적이었습니다. 처음엔 정말 순조로웠거든요.

**지혜:** 그럼 문제가 생긴 건가요?

**박교수:** 맞습니다. 포스팅이 늘어나면서 이상한 일이 발생했습니다. 빌드 중이라는 메시지가 나온 후 몇 시간이 지나도 배포가 되지 않는 거였어요. 특히 사진이 많은 글을 올릴 때마다요. GitHub 로그를 확인해보니 'image transformation' 작업에서 프로세스가 멈춰 있었던 것입니다.

**지혜:** 아, 그럼 이미지 변환 때문이었군요! 왜 그런 일이 일어나는 건가요?

**박교수:** 좋은 질문입니다. Jekyll은 업로드된 이미지를 자동으로 여러 크기로 변환합니다. 데스크톱, 태블릿, 모바일 등 다양한 기기에 최적화하기 위함이죠. 그런데 이 과정이 상당한 시스템 리소스를 소비해요. GitHub Actions의 빌드 환경은 CPU와 메모리가 제한되어 있어서, 특히 고해상도 사진을 많이 올릴 땐 타임아웃되거나 멈추기 쉬운 겁니다.

**지혜:** 그럼 교수님은 어떻게 해결하셨어요?

**박교수:** 세 가지 방법을 차례로 적용했습니다. 첫째, 업로드 전에 이미지를 압축하는 겁니다. ImageMagick 같은 도구로 배치 처리를 하면 5MB짜리 이미지도 300~500KB로 줄일 수 있어요. 이것만으로도 빌드 시간이 절반으로 단축되었습니다.

**지혜:** 와, 그렇게 효과가 크네요!

**박교수:** 네, 정말 놀랐습니다. 둘째는 Jekyll의 설정 파일을 조정하는 것인데, 변환할 이미지 크기를 줄이거나 특정 옵션을 비활성화할 수 있어요. 저는 불필요한 소형 이미지 생성을 줄이고 두 가지 크기만 유지하도록 설정했습니다. 셋째, GitHub에 올리기 전에 반드시 로컬에서 완전히 빌드를 마쳐보는 거예요. 이렇게 하면 실제 배포 환경에서 실패할 일이 거의 없습니다.

**지혜:** 정말 실용적이네요! 이 방법들이 모두 필요한 건가요?

**박교수:** 이미지 압축부터 시작하면 특별한 기술 지식 없이도 즉각적인 효과를 볼 수 있어요. 그 다음에 설정을 조정하고, 마지막으로 로컬 검증을 더하면 완벽합니다. 저처럼 취미로 블로그를 운영하시는 분이라면, 이 문제가 해결됐을 때의 쾌감이 정말 이루 말할 수 없습니다.

**지혜:** 정말 도움이 될 것 같아요! 더 자세한 내용과 구체적인 설정 방법은 블로그 원문에서 확인하실 수 있어요. 노교수님, 오늘 좋은 팁 나눠주셔서 감사합니다!

**박교수:** 고맙습니다. 여러분의 경험담도 댓글로 나눠주시면 좋겠습니다.
