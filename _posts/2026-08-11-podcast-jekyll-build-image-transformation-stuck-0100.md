Jekyll 블로그 빌드가 자꾸 멈춘다면? 이미지 변환 작업의 함정

&nbsp;

### 📌 에피소드 주요 내용
- Jekyll 빌드 중 이미지 변환 작업이 무한 대기하는 현상의 원인은 순차 처리, 리소스 제한, 캐시 문제
- 이미지 사전 처리(리사이징, 품질 조정), 포스트 분산 업로드, 타임아웃 설정 증가 등으로 해결 가능
- 체계적인 최적화 방법 적용으로 빌드 시간을 30분에서 7분으로 단축

### 🎧 전체 대본
**지혜:** 안녕하세요, 저는 진행자 지혜입니다. 오늘은 노교수님과 함께 Jekyll 블로그 운영 중 겪을 수 있는 �흔한 문제에 대해 얘기해보겠습니다. 교수님, 최근에 블로그를 운영하면서 빌드 문제를 겪으셨다고 들었는데요?

**박교수:** 네, 맞습니다. 은퇴 후 기술 블로그를 취미로 시작했는데, GitHub Pages에 포스트를 올릴 때마다 빌드 과정에서 자꾸만 멈춰버리는 현상이 있었어요. 처음엔 단순히 네트워크 문제라고 생각했는데, 알고 보니 이미지 변환 작업의 문제였습니다. 우리가 블로그에 삽입하는 이미지들을 자동으로 최적화하고 여러 형식으로 변환하는 과정에서 작업이 쌓여서 제대로 진행되지 않았던 거죠.

**지혜:** 아, 그럼 어떤 원인들이 있었나요? 왜 이런 일이 발생하는 걸까요?

**박교수:** 크게 세 가지 문제가 있습니다. 첫째, 이미지 변환 작업이 순차적으로 처리되기 때문에 이미지가 많으면 시간이 오래 걸립니다. 제 경우 한 포스트에 15개의 고해상도 이미지가 있었고, 4가지 형식으로 변환하려니 60개의 변환 작업이 필요했던 겁니다. 둘째, GitHub Actions의 무료 플랜은 CPU와 메모리 제한이 있어서 무거운 작업에 취약합니다. 셋째, 캐시 메커니즘이 제대로 작동하지 않으면 매번 처음부터 재처리해야 합니다.

**지혜:** 생각보다 복잡하네요. 그럼 교수님은 어떻게 이 문제를 해결하셨어요?

**박교수:** 효과적이었던 방법들이 몇 가지 있습니다. 가장 먼저 업로드 전 이미지를 사전 처리했어요. 고해상도 사진을 800x600 정도로 리사이징하고 품질을 85% 수준으로 낮춰서 파일 크기를 줄였습니다. 두 번째로는 포스트를 한 번에 여러 개 올리지 말고 한두 개씩 분산해서 올렸어요. 그러면 각 빌드가 충분한 리소스를 할당받을 수 있거든요. 마지막으로 Jekyll 설정 파일을 직접 수정해서 GitHub Actions의 타임아웃 시간을 60분에서 120분으로 늘렸고, 빌드 캐시도 초기화했습니다.

**지혜:** 와, 정말 효과가 있었나요?

**박교수:** 네, 상당했습니다. 빌드 시간을 30분에서 7분으로 단축할 수 있었어요. 기술적인 문제는 처음엔 답답하지만, 사실 디버깅과 최적화의 좋은 기회입니다. 혹시 비슷한 문제를 겪으신다면 이런 방법들을 차례로 시도해보고, GitHub의 공식 이슈 페이지에서 관련 사례를 찾아보시기를 권장합니다.

**지혜:** 정말 유용한 조언이네요! 더 자세한 내용은 노교수님의 블로그 원문에서 확인하실 수 있어요. 오늘 말씀해주셔서 감사합니다!
