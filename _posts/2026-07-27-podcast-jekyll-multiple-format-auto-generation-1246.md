### 📌 에피소드 주요 내용
- Jekyll 블로그에서 하나의 포스트로 HTML, iCal, JSON 등 여러 파일 형식을 동시에 자동 생성하는 방법
- 커스텀 플러그인(multi_format_generator.rb)을 이용한 실제 구현 방식과 프론트매터 설정
- GitHub Pages 배포 제약, 로컬 빌드 필요성 등 한계점 및 대안 검토

&nbsp;

### 🎧 전체 대본

**지혜:** 안녕하세요, 팟캐스트 '기술 이야기'입니다. 오늘은 노교수님과 함께 블로그 운영 중 마주친 흥미로운 기술 문제에 대해 이야기해볼 텐데요. 교수님, 안녕하세요!

**박교수:** 안녕하세요, 지혜님. 반가워요. 은퇴 후 Jekyll 블로그를 시작했는데, 예상 밖의 문제들이 많았어요. 강의 노트와 경제 칼럼을 정리하다 보니 학생들이 강의 일정을 달력에 넣고 싶다고 하고, 일부 독자들은 PDF 다운로드를 원했거든요.

**지혜:** 아, 그래서 한 포스트마다 여러 파일 형식이 필요했군요! HTML, iCal, PDF 이렇게요?

**박교수:** 정확합니다. 문제는 이 세 가지를 모두 수동으로 만들어야 했다는 거예요. 그리고 강의 일정이 바뀌면 세 개의 파일을 모두 수정해야 했으니, 일관성을 유지하기가 정말 힘들었습니다. Jekyll의 기본 구조가 하나의 마크다운 파일에서 하나의 출력 파일만 생성하도록 설계되어 있기 때문이었죠.

**지혜:** 그럼 어떻게 해결하셨어요?

**박교수:** Jekyll의 플러그인 시스템을 활용했어요. multi_format_generator.rb라는 커스텀 플러그인을 만들어서, 포스트의 프론트매터에 formats: [html, ical, json]이라고 지정하면 자동으로 여러 형식의 파일들이 생성되도록 했습니다. _layouts 폴더에 각 형식별 레이아웃 파일을 준비하고, 루비 스크립트로 포스트마다 지정된 형식의 파일들을 생성하게 한 것이죠. 이제 학생들은 페이지의 버튼을 클릭하면 바로 자신의 캘린더에 일정을 추가할 수 있어요.

**지혜:** 와, 완벽한 해결책이네요! 그런데 단점도 있나요?

**박교수:** 물론입니다. 플러그인을 사용하면 GitHub Pages에서 직접 배포할 수 없고, 로컬에서 빌드한 후 업로드해야 합니다. 더 간단한 대안으로는 같은 콘텐츠를 여러 마크다운 파일로 나누어 관리하는 방법도 있지만, 그것도 유지보수가 어렵죠. 다행히 최근에는 Jekyll 커뮤니티에서 이 문제에 대한 더 나은 해결책들이 논의되고 있고, 일부 테마도 다중 형식 출력을 지원하기 시작했습니다.

**지혜:** 은퇴 후 블로그 운영이 이렇게 깊이 있는 기술 문제와 연결될 줄은 정말 흥미롭네요. 더 자세한 내용은 블로그 원문에서 확인하실 수 있으니, 많은 분들이 참고하시길 바랍니다. 오늘 말씀해주셔서 감사합니다, 교수님!

**박교수:** 지혜님, 좋은 질문 감사해요. 혹시 같은 문제로 고민하시는 분들이 있다면, 자신의 상황에 맞는 방법을 선택해서 시도해보시기를 권장합니다.
