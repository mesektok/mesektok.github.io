## 서론: 은퇴 후 블로그를 시작한 이유

저는 대학에서 40년간 컴퓨터공학을 가르친 후 작년에 은퇴했습니다. 여유 있는 생활 속에서 개발 커뮤니티에 기여하고 싶다는 마음이 들어, GitHub Pages와 Jekyll로 기술 블로그를 시작했습니다. 그런데 처음 몇 주간 정말 고생했습니다. 포스트를 작성하고 푸시할 때마다 GitHub에서 빌드 실패 이메일이 날아왔거든요. 젊은 시절에는 경험했지만, 오랜 시간이 지나 기억이 흐릿했던 이슈들이 다시 나타난 것입니다. 이 글에서는 제가 직접 경험한 Jekyll 빌드 실패의 원인들과 해결 방법을 여러분과 나누고자 합니다.

## GitHub Pages 빌드 실패의 첫 번째 원인: Ruby 버전 불일치

가장 많이 마주친 문제는 로컬 개발 환경과 GitHub Pages 서버의 Ruby 버전 차이였습니다. 제 맥북에는 Ruby 3.2가 설치되어 있었는데, GitHub Pages는 Ruby 3.1.x를 사용합니다. 이 버전 차이가 gem 의존성 문제를 일으켜 빌드가 자꾸 실패했습니다.

처음에는 로컬에서 `bundle exec jekyll serve`로 완벽하게 빌드되는데, GitHub에서만 자꾸 실패했습니다. 정말 답답했습니다. 하지만 깨달음의 순간이 왔습니다. 바로 `.ruby-version` 파일을 프로젝트 루트에 생성하는 것입니다. 이 파일에 `3.1.2`라고 명시하고, `rbenv`를 통해 로컬 환경을 맞추니 문제가 해결되었습니다. 또한 `Gemfile.lock` 파일을 반드시 깃허브에 커밋해야 합니다. 이 파일이 없으면 GitHub Pages가 임의로 gem 버전을 선택하게 되어 예기치 않은 호환성 문제가 발생합니다.

## 두 번째 원인: 플러그인과 의존성 관리의 중요성

제 블로그는 Jekyll Chirpy 테마를 사용하고 있습니다. 이 테마는 정말 훌륭하지만, 여러 플러그인에 의존합니다. 저는 처음에 `_config.yml` 파일을 제멋대로 수정하다가 문제가 생겼습니다.

특히 GitHub Pages가 공식 지원하지 않는 플러그인을 활성화했을 때가 그랬습니다. GitHub Pages는 보안상의 이유로 제한된 플러그인만 허용합니다. 저는 `jekyll-paginate-v2`를 사용하려다가 빌드 실패를 겪었습니다. GitHub Pages가 지원하는 플러그인 목록을 확인한 후, 공식 지원 플러그인만 사용하도록 변경했습니다.

또 한 가지 배운 점은 `Gemfile`에서 플러그인을 명확히 선언해야 한다는 것입니다. 저는 모든 의존성을 `Gemfile`에 정의하고, `bundle install`로 설치한 후 커밋합니다. 이렇게 하면 GitHub Pages 서버에서도 동일한 환경을 재현할 수 있습니다.

## 세 번째 원인: 마크다운 파일의 프론트매터 오류

은퇴 후 글쓰기에 다시 집중하다 보니, 마크다운 파일 작성에서 실수가 자주 생겼습니다. Jekyll에서 가장 흔한 실패 원인은 YAML 프론트매터의 포맷 오류입니다. 프론트매터는 파일의 최상단에 `---`로 감싸진 메타데이터입니다.

저는 처음에 프론트매터의 들여쓰기와 콜론(`:`) 다음의 공백 규칙을 무시했습니다. YAML은 매우 까다로운 포맷인데, 예를 들어 `title:"My Post"`처럼 콜론과 값 사이에 공백이 없으면 파싱이 실패합니다. 또한 탭 문자를 사용하면 절대로 안 되고, 반드시 스페이스를 사용해야 합니다.

특히 배열을 다룰 때가 문제였습니다. 태그를 `tags: [tag1, tag2]` 형식으로 쓸 때, 대괄호 안의 공백 규칙을 잘못 이해했다가 빌드 실패를 경험했습니다. 지금은 각 파일을 커밋하기 전에 항상 YAML 검증 도구를 통과시킵니다.

## 빌드 성공을 위한 검증 루틴

이제 저는 포스트를 작성할 때마다 세 가지 검증 단계를 거칩니다. 첫째, 로컬에서 `bundle exec jekyll build`를 실행하여 빌드 가능 여부를 확인합니다. 둘째, 생성된 `_site` 폴더의 HTML 파일들을 샘플링해서 확인합니다. 셋째, GitHub에 푸시하기 전에 잠깐의 휴식을 취하고 마음의 준비를 합니다.

이러한 루틴을 통해 저는 지난 3개월간 빌드 실패 없이 안정적으로 블로그를 운영하고 있습니다. 은퇴 후 얻은 값진 교훈입니다.

여러분도 Jekyll 빌드 실패로 고생하고 계신다면, 위의 세 가지 원인을 차근차근 점검해보세요. 분명히 문제를 해결하는 데 도움이 될 것입니다.
