GitHub 캔버스가 던지는 물음: AI 에이전트 시대에 ‘보이는 일’이 왜 중요할까

&nbsp;

### 📌 에피소드 주요 내용
- AI 에이전트와 인간의 협업에서 채팅만으로는 작업 추적이 어렵다
- GitHub 캔버스는 진행 중인 일을 시각화하고 상태를 명시적으로 만드는 솔루션
- 비용 효율성은 명확한 작업 추적과 불필요한 재실행 제거에서 나온다

### 🎧 전체 대본
**박교수:** 안녕하세요, 지혜. 오늘은 흥미로운 주제를 가져왔어요. GitHub 캔버스라는 새로운 도구에 대해 이야기해볼 건데, 이게 단순한 UI 개선이 아니라 AI와 인간이 함께 일하는 방식 자체를 바꾸려는 시도라고 봅니다.

**지혜:** 오, 정확히 어떤 의미에서 그렇다고 생각하세요?

**박교수:** 채팅으로 AI와 대화하는 시대는 이미 과거가 되었다는 거죠. 처음엔 '이거 해줘', '다시 해봐' 하는 상호작용이 빠르고 자연스러워 보입니다. 하지만 작업이 커지면서 문제가 터져요. 무엇이 계획이었는지, 뭐가 검증됐는지, 뭐가 남았는지—이 모든 게 긴 채팅 스크롤 속에 묻혀버립니다.

**지혜:** 아, 그래서 기록 추적이 힘들어지는군요.

**박교수:** 그뿐만 아니라 AI 에이전트가 변경사항을 인간이 검토할 수 있는 속도보다 더 빨리 만들어내면 어떻게 될까요? '뭐가 돌았는지, 뭐가 바뀌었는지, 누가 승인했는지' 추적 자체가 불가능해져요. 바로 여기서 GitHub의 캔버스가 제안하는 거입니다.

**지혜:** 캔버스가 구체적으로 뭘 해주는 건가요?

**박교수:** 캔버스는 개발자와 에이전트가 공유된 표면에서 상호작용하게 하는 거예요. 채팅을 일이 일어나는 유일한 장소로 취급하지 말고, 진행 중인 일을 시각적으로 보고, 조종하고, 승인 가능하게 만드는 거죠. 가장 중요한 건 '상태를 명시적이고 지속 가능하게 만든다'는 개념입니다. 지금 뭐가 진행 중인지, 다음 단계가 뭔지, 누가 결정을 내려야 하는지—한눈에 볼 수 있어야 한다는 겁니다.

**지혜:** 그럼 결국 효율성이 올라가는 건가요?

**박교수:** 네, 맞습니다. 불필요한 재검토, 불명확한 상태 때문의 재실행, 누가 뭘 승인했는지 몰라서 반복하는 작업—이 모든 게 비용을 먹어치우니까요. 다만 아직 남은 질문들이 있어요. 캔버스의 견고함이 오히려 팀에게 버거울 수도 있고, AI 에이전트가 정말 이렇게 계획적으로 단계별 진행이 가능할지도 미지수입니다.

**지혜:** 흥미로운 지적이네요. 채팅 시대가 완전히 끝나는 건 아니겠지만, 실제 워크플로우 운영 차원에선 '누가, 언제, 뭘, 왜 했는가'를 추적할 수 있는 구조가 필수가 되어가는 거군요. 더 자세한 내용과 노교수님의 분석은 블로그 원문에서 확인하실 수 있어요!
