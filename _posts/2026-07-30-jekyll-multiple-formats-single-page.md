## 은퇴 후 발견한 Jekyll의 한계

저는 대학에서 30년간 정보시스템학을 가르쳤습니다. 은퇴한 지 3년째, 학생들을 위해 무료 온라인 강좌 자료를 정리하는 프로젝트를 시작했습니다. GitHub Pages와 Jekyll을 선택한 것은 비용이 들지 않고 버전 관리가 쉽기 때문이었습니다.

문제는 예상치 못했습니다. 강의 일정을 게시할 때, 학생들은 HTML 페이지에서도 보고 싶어 하고, 동시에 자신의 캘린더 앱(Google Calendar, Outlook)에 자동으로 추가할 수 있는 iCal 형식도 원했습니다. 같은 내용을 두 번 관리하는 것은 너무 비효율적이었습니다.

"하나의 포스트로 여러 형식의 파일을 만들 수 없을까?" 이것이 제가 Jekyll 공식 이슈 게시판에서 발견한 3041번 이슈였습니다.

## 문제의 본질: Jekyll의 단일 형식 제약

Jekyll은 기본적으로 마크다운 파일 하나당 하나의 출력 형식(보통 HTML)만 생성합니다. 여러분이 `_posts/2026-07-30-lecture-schedule.md` 파일을 만들면, Jekyll은 기본적으로 같은 이름의 HTML 파일만 만듭니다.

하지만 현실의 콘텐츠는 더 복잡합니다. 학술 자료는 웹 버전, PDF 버전, 인쇄 버전이 필요합니다. 이벤트 정보는 HTML과 iCal이 동시에 필요합니다. 제품 카탈로그는 웹페이지와 JSON 피드 모두 필요합니다.

GitHub의 이슈에서 제안된 해결책은 레이아웃 시스템을 확장하는 것이었습니다. 현재 Jekyll에서는 `layout: post`라는 한 가지만 지정할 수 있지만, `layouts: [post, ical]` 같은 다중 레이아웃 지정을 허용한다면 어떨까요?

## 현재 가능한 해결책들

### 1. 플러그인을 활용한 커스텀 제너레이터

제 경우에는 Jekyll 플러그인으로 해결했습니다. `_plugins` 폴더에 루비 스크립트를 작성하여 원본 마크다운을 파싱한 후 여러 형식으로 변환하는 방식입니다.

```ruby
Jekyll::Hooks.register :posts, :post_write do |post|
  # HTML 생성 후, 같은 내용으로 iCal도 동시에 생성
  generate_ical_from_post(post)
end
```

이 방식은 작동하지만, Jekyll의 의도된 사용법이 아니라는 점에서 약간의 불편함이 있습니다.

### 2. 출력 폴더 다중화 전략

또 다른 접근은 `_config.yml`에서 여러 출력 폴더를 설정하고, 각각에 대해 다른 레이아웃을 적용하는 것입니다. 예를 들어, 같은 포스트가 `_site/blog/`, `_site/calendar/` 두 폴더에 서로 다른 형식으로 생성되도록 합니다.

### 3. 자동화 스크립트 결합

가장 실용적인 방법은 Jekyll 빌드 후 셸 스크립트나 Node.js로 후처리 단계를 추가하는 것입니다. Jekyll이 HTML을 생성한 후, 추가 스크립트가 마크다운 메타데이터를 읽어 iCal, JSON, PDF 등으로 변환합니다.

## 실제 적용 경험과 조언

저는 세 번째 방법을 최종 선택했습니다. GitHub Actions 워크플로우에 다음과 같은 단계를 추가했습니다:

1. Jekyll로 HTML 생성
2. Node.js 스크립트로 마크다운 파일들을 순회
3. Front Matter 데이터를 추출해 iCal, JSON으로 변환
4. 결과물을 `_site` 폴더에 배치

이렇게 하면 유지보수도 간편합니다. 강의 일정을 수정할 때는 마크다운 파일 하나만 수정하면, 빌드 프로세스가 자동으로 모든 형식을 업데이트합니다.

대학원 때 배운 이론과 달리, 실무에서는 완벽한 솔루션보다 작동하는 솔루션이 중요합니다. Jekyll의 제약을 원망하기보다, 그 위에 얹어서 필요한 기능을 만드는 것이 더 효율적입니다.

혹시 여러분도 한 페이지에서 여러 형식을 생성해야 한다면, 저의 GitHub 저장소에서 실제 구현 코드를 참고하실 수 있습니다. 더 나은 방법을 발견하셨다면 댓글로 공유해주세요.
