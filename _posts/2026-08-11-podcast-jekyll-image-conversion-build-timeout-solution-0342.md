### 📌 에피소드 주요 내용

- 이미지 사전 처리, 포스트 분산 업로드, 타임아웃 설정 확대로 빌드 시간 30분에서 7분으로 단축
- GitHub Actions의 리소스 제약과 순차 처리로 인한 성능 병목 현상 확인

### 🎧 전체 대본
**지혜:** 안녕하세요, 팟캐스트 '기술 이야기' 진행자 지혜입니다. 오늘은 특별히 노교수님을 모셨습니다. 교수님, 반갑습니다!

**박교수:** 안녕하세요. 저는 은퇴 후 취미로 기술 블로그를 운영하고 있는데, 최근에 꽤 흥미로운 문제를 겪었습니다. GitHub Pages에 포스트를 올릴 때마다 빌드 과정에서 멈춰버리는 현상이었거든요. 처음엔 네트워크 문제인 줄 알았지만, 결국 이미지 변환 작업이 원인이었습니다.

**지혜:** 오, 그런 일이 있었군요! 그럼 정확히 어떤 문제였나요?

**박교수:** Jekyll이나 Gatsby 같은 정적 사이트 생성기에서는 이미지를 자동으로 최적화하는 기능이 있습니다. 특히 Chirpy 테마를 사용할 때 더욱 그렇죠. 문제는 이 작업 큐가 제대로 처리되지 않을 때 발생합니다. 제 경우, 하루에 3~4개의 포스트를 일괄 업로드했는데, 이미지 변환 작업이 쌓여서 진행이 안 됐거든요. 한 포스트에 15개의 고해상도 이미지가 있었고, 4가지 형식으로 변환하도록 설정되어 있었습니다. 단순히 60개의 이미지 변환 작업이 필요했던 셈이죠.

**지혜:** 와, 그렇게 많은 작업이 한 번에 쌓이면 당연히 멈출 수밖에요. 그럼 어떻게 해결하셨어요?

**박교수:** 여러 방법을 시도했습니다. 첫째, 블로그에 올리기 전에 이미지를 미리 최적화했습니다. 고해상도 사진을 800x600으로 리사이징하고 품질을 85% 수준으로 낮췄죠. 둘째, 포스트를 한두 개씩 나눠서 올렸습니다. 이렇게 하면 각 빌드가 충분한 리소스를 받을 수 있습니다. 셋째, Jekyll 설정 파일을 수정해서 타임아웃 시간을 60분에서 120분으로 늘렸고, GitHub Actions 캐시를 초기화했습니다. 이 모든 방법을 종합적으로 적용한 후 빌드 시간을 30분에서 7분으로 단축할 수 있었습니다.

**지혜:** 정말 대단한 개선이네요! 혹시 이런 문제가 흔한 편인가요?

**박교수:** 네, GitHub의 공식 이슈 트래커를 보면 여러 사용자가 비슷한 문제를 보고했습니다. 특히 이미지 변환 작업이 병렬로 처리되지 않고 순차적으로 진행되기 때문입니다. 또한 GitHub Actions의 무료 플랜은 CPU와 메모리에 제한이 있어서 무거운 작업에 쉽게 걸립니다. 기술 커뮤니티의 경험과 지혜가 이런 순간에 가장 귀한 자산이라고 봅니다.

**지혜:** 정말 유용한 조언 감사합니다, 교수님. 더 자세한 내용과 추가 팁들은 블로그 원문에서 확인하실 수 있어요. 청취자 여러분도 Jekyll 블로그 빌드 문제로 고민하신다면 참고해보세요!
