## 은퇴 후 발견한 Jekyll의 답답한 한계

지난 3월, 서울대 물리학과 명예교수인 이 교수(72)가 찾아왔습니다. 은퇴 후 개인 블로그를 운영하던 중 마주친 문제였습니다. 대학 때부터 연구한 천문 관측 일정을 블로그에 공유하고 싶었는데, 방문자들이 자신의 캘린더 앱에 바로 추가하길 원했거든요. HTML 페이지와 iCal 형식을 동시에 생성해야 했던 겁니다.

"블로그 포스트 하나로 웹페이지도 만들고, 캘린더 파일도 만들 수 있으면 좋지 않을까요?" 이 교수의 질문은 2014년 Jekyll 공식 깃허브에 올라온 이슈 #3041과 정확히 일치했습니다. 당시 Jekyll은 한 페이지 당 하나의 출력 형식만 지원했기에, 많은 사용자가 이를 아쉬워했습니다.

지금 이것이 중요한 이유를 설명하겠습니다.

## 현실에서 마주치는 다중 형식 생성의 필요성

생각해보면, 단순한 블로그를 넘어 다양한 콘텐츠를 서빙해야 하는 경우가 많습니다.

**학술 자료 공유**: 교수님들이 운영하는 교과 블로그는 HTML뿐 아니라 PDF, Markdown, BibTeX 형식이 필요합니다. 학생들이 인용 정보를 바로 받아가면서도 웹에서도 읽을 수 있어야 하기 때문입니다.

**행사 정보 배포**: 시니어 세대가 운영하는 모임 블로그라면 HTML 소식, iCal 캘린더, RSS 피드를 동시에 필요로 합니다. 마을 주민 모임이나 동창회는 특히 그렇습니다.

**메타데이터 노출**: 단순히 HTML만으로는 메타데이터(JSON-LD, Dublin Core 등)를 별도로 관리해야 하는데, 같은 포스트에서 여러 형식을 생성할 수 있다면 데이터 일관성도 보장됩니다.

이 교수의 경우, 천문 관측 일정을 매월 포스팅할 때마다 HTML 페이지를 만들고, 따로 iCal 파일을 수동으로 작성했어야 했습니다. 매우 비효율적이었죠.

## 실무 해결책: Layouts를 활용한 다중 형식 생성

Jekyll은 2024년 현재, 공식적으로는 여전히 제한적이지만, 실무에서는 여러 방법으로 이 문제를 우회하고 있습니다.

**첫 번째 방법: 커스텀 플러그인 활용**

Ruby를 이용해 Jekyll 플러그인을 작성하면, 한 포스트를 여러 형식으로 변환할 수 있습니다. 예를 들어, 이 교수는 다음과 같은 플러그인을 개발했습니다. `_plugins` 폴더에 `multi_format_generator.rb`를 만들어, 매 빌드 때 마크다운 포스트를 읽고 HTML과 iCal을 동시에 생성하게 했습니다.

```ruby
Jekyll::Hooks.register :posts, :post_write do |post|
  # iCal 생성 로직
end
```

**두 번째 방법: 별도 컬렉션 구성**

`_config.yml`에서 `collections`을 활용하되, 각각 다른 `output: true` 설정과 `output_ext`를 지정합니다. 예를 들어 같은 마크다운 파일이 `_posts` 컬렉션에서는 HTML로, `_events` 컬렉션에서는 iCal로 변환되도록 구성하는 방식입니다.

**세 번째 방법: 빌드 후 처리(Post-processing)**

Jekyll이 생성한 HTML을 기반으로, 빌드 후 스크립트(Python이나 Node.js)를 실행해 추가 형식을 생성합니다. 이 방식은 가장 안정적이며, 많은 정적 사이트 생성기에서 사용하는 패턴입니다. 이 교수도 이 방법을 최종 선택했습니다.

시간이 흘러 이 교수의 천문 관측 블로그는 매달 HTML 포스트와 함께 자동으로 iCal 파일이 생성되기 시작했습니다. 블로그 방문자들은 이제 "이 관측 일정을 내 캘린더에 추가" 버튼을 클릭하면, 즉시 자신의 캘린더 앱에 정보가 동기화됩니다.

## 미래를 향한 작은 개선

Jekyll 커뮤니티도 이 필요성을 인식했습니다. 최신 버전에서는 `output_ext` 설정이 개선되고, 향후 네이티브로 다중 형식을 지원할 가능성이 논의 중입니다. 하지만 지금 필요하다면, 위 세 가지 방법 중 자신의 기술 수준과 요구사항에 맞는 것을 선택하면 됩니다.

특히 시니어 세대가 운영하는 블로그나 커뮤니티 사이트에서는 접근성이 중요합니다. 방문자들이 다양한 형식으로 콘텐츠를 소비할 수 있도록 하는 것이 좋은 UX입니다.

여러분의 Jekyll 블로그에서 비슷한 다중 형식 필요성을 느낀다면, 위 방법들을 직접 시도해보고 댓글로 여러분의 경험과 발견을 공유해주세요.
